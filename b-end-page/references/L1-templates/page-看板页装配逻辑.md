# L1 · 看板页装配逻辑

本文件描述**看板页**如何从模块库装配成页面。所有模块的通用规则（核心视觉、可配参数）统一维护在 L2 模块规范中，本文件只负责说明「看板页用哪种编排模式、按什么逻辑组合模块、用什么外壳承载」。

---

## 〇、技术栈判断（最先执行）

> ⚠️ **生码前必须先确认技术栈**，不同技术栈的组件 API、CSS 类名前缀、DOM 结构存在显著差异。沿用主 SKILL.md §4.0 的框架探测方式，此处不重复。

## 一、装配逻辑：默认外壳 + 两步装配

### 默认外壳：全局导航（G-1 顶部导航 + G-2 侧边栏）

> ⚠️ **任何看板页默认包含顶导和侧导**。大屏/驾驶舱场景可去掉侧导，但需用户明确要求。

```
G-1 顶部导航（fixed 顶部，52px 高）
  └─ G-2 侧边栏（fixed 左侧，168px / 收起 60px）
      └─ app-content（主内容区，灰底 #F3F3F4）
          └─ 看板内容区（筛选器 → 指标/图表/表格 按编排模式排布）
```

**加载规则**：生成看板页时，默认加载 G-1 和 G-2。顶导和侧导的菜单数据根据业务场景合理虚构，当前页面对应的菜单项设为选中态。大屏/驾驶舱场景用户明确要求"不要侧栏"时省略 G-2。

### 两步装配（编排模式 + 模块）

```
第一步（主维度）：先定编排模式 → 数据通览 / AI总结 / 筛选+表格 / 工作台
          以"图表 vs 表格谁是主角""纯只读 vs 可操作""数据门户 vs 功能门户"为判断依据

第二步（按需叠加）：扫描 prompt，按数据可视化意图匹配 D/G/W 模块
          用户每多描述一项数据维度 → 多叠加一个对应图表模块
          叠加受编排模式约束：工作台模式不叠加重型图表，筛选+表格模式图表不超过2个
```

> **编排模式是约束，模块是在约束内的填充。** 先决定用哪种模式，再在模式内按用户描述叠加模块——不需要先推断"看板类型"再套底座，直接读 prompt 里说了什么、就叠什么模块。

## 二、第一步：选编排模式（四选一）

这是装配的主维度。不同模式决定了筛选器复杂度、图表数量、表格角色和整体布局结构。

| 编排模式 | 图表角色 | 表格角色 | 筛选复杂度 | 布局结构 | 典型场景 |
|---------|---------|---------|-----------|---------|---------|
| 数据通览（Overview） | 主角（70%+，多类型） | 配角（可选下钻） | 简单档 | 单列纵向 + Tab分组 | 综合驾驶舱、经营概览、多维分析 |
| AI总结（AI Summary） | 主角（带AI诊断卡） | 配角 | 简单档 | 单列纵向 | AI智能看板、洞察摘要 |
| 筛选+表格（Filter+Table） | 配角（0~2个） | 主角（60%+，可操作） | 复杂档 | 单列纵向 | 目标管理、预算监控、管理型看板 |
| 工作台（Workbench） | 配角（轻量迷你图） | 配角（待办列表） | 无/简单 | 主-侧分栏（右侧240px sticky） | 工作台首页、门户、快捷操作中心 |

**判断口诀**：

> 看到「驾驶舱」「综合大屏」「数据通览」「多维度看板」「尽量用上各种图表」「经营概览」「生意大盘」→ **数据通览**
> 看到「AI诊断」「智能总结」「洞察摘要」「AI 看板」→ **AI总结**
> 看到「目标看板」「预算进度」「筛选+表格」「管理型看板」「可以操作/修改数据的看板」「复杂筛选」→ **筛选+表格**
> 看到「工作台」「首页」「门户」「快捷入口」「运营首页」「功能导航页」→ **工作台**

> **优先级原则**：用户明确要求某种模式时直接采用；未指定时按数据形态推断——图表多且只读 → 数据通览；表格为主且需操作 → 筛选+表格；偏入口导航 → 工作台；有 AI 诊断卡 → AI 总结。

> **模式间互斥规则**：数据通览命中"可操作/修改数据"时，应切换到筛选+表格模式；筛选+表格模式命中"多种图表类型"时，应切换到数据通览模式；工作台模式不兼容重型图表。

## 四、编排模式 × 模块：约束自检

| 编排模式 | 可叠加的模块 | 约束提示 |
|---------|-------------|---------|
| 数据通览 | 全部 D-1~D-15 + G-3(简单档) + G-4(可选) | ⚠️ 图表多时必须按语义分Tab，不单屏堆砌；类目色 ≤ 7 |
| AI总结 | D-11(必须) + D-1 + D-3 + D-9 + G-3(简单档) | ⚠️ D-11 必须放在最顶部，作为首屏焦点 |
| 筛选+表格 | G-3(复杂档) + G-4(主体) + D-1(可选,≤2) + D-3(可选,≤1) | ⚠️ 图表不超过2个；表格必须带操作列；筛选必须用复杂档 |
| 工作台 | W-1~W-7 + D-1(迷你图变体) + G-4(可选,轻量) | ⚠️ 不放重型图表(D-3~D-15)；主-侧分栏布局；D-1 用「带迷你图」变体 |

> 数据通览模式命中"可操作/修改数据"时，自动切换到筛选+表格模式。
> 筛选+表格模式命中"多种图表类型"时，自动切换到数据通览模式。

## 五、装配示例（按编排模式分组）

以下示例先按**编排模式**归类，体现「模式是主维度」；每个示例再展示「扫描 prompt → 直接叠加模块」。

### （一）数据通览 —— 图表密集 / 纯展示

**例1 · 经营概览看板**

Prompt：「做一个经营概览看板，展示核心指标、趋势、构成、分布等多维度数据」

- 编排模式：**数据通览**（图表多、纯展示、只读）
- 按需叠加：基础底座 → G-3(简单档) + D-1；"趋势" → D-3；"构成" → D-4 + D-7；"分布" → D-10 + D-14；"进度" → D-2 + D-13
- **最终**：数据通览[ G-3(简单) + D-1 + Tab{ 趋势: D-3+D-5 | 构成: D-4+D-7 | 分布: D-10+D-12 | 进度: D-2+D-13 } + G-4(可选) ]

### （二）AI总结 —— AI诊断 + 数据佐证

**例2 · AI 经营诊断看板**

Prompt：「做一个智能分析看板，顶部有 AI 总结，下面展示指标和趋势来佐证 AI 的结论」

- 编排模式：**AI总结**（AI诊断卡 + 数据佐证）
- 按需叠加：基础底座 → G-3(简单档) + D-11(必须)；"指标" → D-1；"趋势" → D-3；"排名" → D-9
- **最终**：AI总结[ G-3(简单) + D-11 + D-1 + D-3 + D-9 ]

### （三）筛选+表格 —— 表格为主 / 可操作

**例3 · 目标管理看板**

Prompt：「目标管理看板，复杂筛选条件，看完成率指标，底部表格可以编辑和审批」

- 编排模式：**筛选+表格**（表格为主、可操作、复杂筛选）
- 按需叠加：基础底座 → G-3(复杂档) + G-4(主体)；"完成率指标" → D-1(轻量)；"编辑和审批" → G-4 操作列
- **最终**：筛选+表格[ G-3(复杂) + D-1(可选) + G-4(操作列: 编辑/审批) ]

### （四）工作台 —— 门户导航 / 快捷操作

**例4 · 运营工作台**

Prompt：「运营首页工作台，有欢迎栏、常用功能入口、待办事项、最新公告」

- 编排模式：**工作台**（门户导航、快捷操作、主-侧分栏）
- 按需叠加：基础底座 → G-1+G-2 + W-1；"常用功能入口" → W-3；"待办事项" → W-4；"最新公告" → W-5
- **最终**：工作台[ 左列: W-1+W-3+D-1(迷你图) | 右栏: W-4+W-5 ]

## 六、装配后处理（页面级补强规则）

### 6.1 图表分组 Tab（数据通览模式专用）

**判断规则**：当数据通览模式下的图表模块 **超过 4 个**时，必须按数据语义（趋势/构成/分布/进度）分组到 MTD Tabs，每组 2~4 张图。≤4 个可直接纵向排列。

分组建议：

| 语义分组 | 典型图表 |
|---------|---------|
| 趋势 | D-3 折线/面积 + D-5 双轴组合 |
| 构成 | D-4 柱状 + D-7 饼图/环图 + D-9 排名条形 |
| 分布 | D-10 散点 + D-12 雷达 + D-14 热力图 + D-15 玫瑰图 |
| 进度 | D-2 环形进度 + D-13 水波球 |
| 转化 | D-6 漏斗 |

### 6.2 信息递进（所有模式通用）

看板页应遵循「概览 → 多维探索 → 明细下钻」的信息递进原则：顶部放 D-1 概览指标（概括数字），中间放 D-3~D-15 多维图表（探索分析），底部可选放 G-4 数据表格（明细下钻）。

### 6.3 工作台右侧边栏规则

工作台模式的右侧边栏固定 240px 宽、`position: sticky; top: 16px`。模块堆叠顺序固定：W-4（今日待办）→ W-5（最新公告）→ W-6（最新动态）。

### 7.1 数据通览（Overview）

**适用场景**：综合驾驶舱、数据大屏、经营概览、多维分析、区域/选址分析。

**核心特征**：图表密集、类型丰富（折线/柱/环/雷达/热力等）；筛选简单（时间段 + 1~2 个维度下拉）；纯展示/只读，不含操作按钮；信息递进：概览指标 → 多维图表探索 → 明细补充。

**页面骨架**：

```
┌─────────────────────────────────────────────────┐
│ G-1 顶部导航                                      │
├─────────────────────────────────────────────────┤
│ G-3 筛选器栏（简单档：快捷时间段 + 区域/维度）     │
├─────────────────────────────────────────────────┤
│ D-1 顶部核心指标（4~6 张卡片）                     │
├─────────────────────────────────────────────────┤
│ mtd-tabs（按数据语义分组）                         │
│ ├─ ① 趋势  → D-3 面积/折线(span14) + D-5 双轴(span10)│
│ ├─ ② 构成  → D-4 柱状(span12) + D-7 饼图(span12)   │
│ ├─ ③ 分布  → D-10 散点(span14) + D-12 雷达(span10)  │
│ └─ ④ 进度  → D-2 进度(span12) + D-13 水波球(span12) │
├─────────────────────────────────────────────────┤
│ G-4 数据表格（全宽，可排序+分页，仅辅助下钻） ← 可选 │
└─────────────────────────────────────────────────┘
```

**模块组装**：

```
G-1 顶部导航          ← 通用骨架
G-2 侧边栏            ← 可选（大屏可去掉）
G-3 筛选器栏（简单档）  ← 见 General3-filter-bar.md
D-1 核心指标卡片组      ← 见 Dashboard1-metric-cards.md
D-3 趋势图            ← 或放入 Tab，见 Dashboard3-trend.md
D-5 双轴组合图         ← 或放入 Tab，见 Dashboard5-combo.md
D-4 柱状图            ← 或放入 Tab，见 Dashboard4-bar.md
D-9 排名条形图         ← 或放入 Tab，见 Dashboard9-rank-bar.md
D-7 饼图/环图          ← 或放入 Tab，见 Dashboard7-pie-donut.md
D-10 气泡散点          ← 或放入 Tab，见 Dashboard10-scatter.md
D-12 雷达图            ← 按需，见 Dashboard12-radar.md
D-14 热力图            ← 按需，见 Dashboard14-heatmap.md
D-15 玫瑰图            ← 按需，见 Dashboard15-rose.md
D-2 进度展示 / D-13 水波球 ← 按需
D-6 转化漏斗           ← 按需，见 Dashboard6-funnel.md
G-4 数据表格           ← 可选，底部辅助明细，见 General4-data-table.md
```

**用到的图表类型**：

| 语义分组 | 图表 | 所属模块 | G2 type |
|---------|------|---------|---------|
| 趋势 | 折线/面积趋势 | D-3 | `line`/`area` |
| 趋势 | 双轴组合 | D-5 | `type:'view'` + `children:[interval, line]` |
| 构成 | 柱状图（含堆叠/分组变体） | D-4 | `interval`(+`stackY`/`dodgeX`) |
| 构成 | 排名条形 | D-9 | `interval` + `coordinate:{transform:[{type:'transpose'}]}` |
| 构成 | 饼图/环图 | D-7 | `interval` + `coordinate:{type:'theta'}` |
| 分布 | 气泡散点 | D-10 | `point`(`encode.size`) |
| 分布 | 玫瑰图 | D-15 | `interval` + `coordinate:{type:'polar', innerRadius:0.2}` |
| 分布 | 雷达画像 | D-12 | `area` + `coordinate:{type:'polar'}` |
| 分布 | 活跃热力图 | D-14 | `cell` |
| 进度 | 环形进度/进度条列表 | D-2 | `gauge`/自定义进度条 |
| 进度 | 水波球 | D-13 | `liquid` |
| 转化 | 转化漏斗 | D-6 | `interval` + funnel + `symmetryY` |

> 每类图表的 G2 v5 关键写法与特殊数据结构踩坑，分别见各自 `DashboardN-xxx.md` 文件的「## MTD 实现」章节；图表外壳统一规格见 `DashboardChartCard.md`。

**生成要点**：

1. 图表多 → 分组 Tab，不要单屏堆图：按趋势/构成/分布/进度把图归类，每组聚焦一类语义。
2. 主图 span14 / 副图 span10，或对半 span12；`mtd-row :gutter="16"`。
3. 所有图表共用 `ChartCard` 外壳（D-8 堆叠进度条除外）+ `useG2Chart` 基座，颜色一律取自 `chartTokens`，类目色 ≤ 7。
4. 顶部留 D-1 概括数字，底部可接 G-4 辅助下钻明细，形成「概览→多维探索→落细节」的信息递进。
5. 大屏场景可去 G-2 侧栏、用深色背景变体（仍遵守色板 token）。
6. 筛选只用简单档（单行 flex），不需要复杂筛选。
7. 本模式**不含**快捷入口网格（W-3）和操作引导卡（W-2），那些属于工作台模式。

**自检**：

- [ ] 图表按语义分到 Tab（趋势/构成/分布/进度），未单屏堆砌。
- [ ] 每张图走 ChartCard + useG2Chart（D-8 除外），颜色取自 chartTokens。
- [ ] 筛选为简单档（单行），无复杂分组/方案/收起。
- [ ] 纯展示/只读，无增删改操作按钮。
- [ ] 顶部 D-1 概览、底部可选 G-4 明细形成信息递进。
- [ ] 无快捷入口网格（W-3），无操作引导卡（W-2）。

### 7.2 AI总结（AI Summary）

**适用场景**：智能分析看板、AI 洞察页、经营诊断、智能运营大盘。

**核心特征**：顶部 AI 诊断摘要卡（D-11），紫色渐变背景，左侧文字洞察 + 右侧关键指标；下方与数据通览结构相似：指标卡 + 趋势图 + 排名/占比；筛选简单（简单档）；只读展示，不含操作。

**与数据通览的本质差异**：

| | 数据通览 | AI总结 |
|---|---|---|
| 首屏焦点 | D-1 指标卡片 | D-11 AI 诊断摘要卡 |
| AI 洞察 | 无 | 有（顶部占显著位置）|
| 图表数量 | 多（Tab 分组） | 中等（不一定需要 Tab 分组）|

### 7.3 筛选+表格（Filter + Table）

**适用场景**：目标管理、预算监控、KPI 进度、数据查询+操作、明细管理型看板。

**核心特征**：筛选复杂（复杂档：多行分组 + 多控件 + 快捷方案 + 收起/展开）；图表少（0~2 个，仅指标卡或进度/趋势，非主体）；底部大表格（全宽，带操作列：编辑/审批/删除等）；以操作/修改为主，非纯只读。

**与数据通览的本质差异**：

| | 数据通览 | 筛选+表格 |
|---|---|---|
| 核心目的 | 看数据（只读） | 查数据+改数据（可操作）|
| 筛选复杂度 | 简单档 | **复杂档** |
| 图表角色 | 主角（占 70%+） | 配角（0~2 个，占 20%）|
| 表格角色 | 辅助（可选） | **主角**（占 60%+）|
| 表格可操作 | 仅排序/下钻 | 编辑/审批/删除/状态变更 |

**页面骨架**：

```
┌─────────────────────────────────────────────────┐
│ G-1 顶部导航                                      │
├─────────────────────────────────────────────────┤
│ G-3 复杂筛选器（多行分组+方案+收起）                 │
├─────────────────────────────────────────────────┤
│ D-1 指标卡片（可选，1~2 个轻量）                    │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐         │
│ └──────────┘ └──────────┘ └──────────┘         │
├─────────────────────────────────────────────────┤
│ D-3 趋势图（可选，全宽）                            │
├─────────────────────────────────────────────────┤
│ G-4 内联操作栏（统计+批量操作+新增）                  │
│ G-4 表格主体（可编辑+操作列，全宽）                   │
│ G-4 内联分页器                                     │
└─────────────────────────────────────────────────┘
```

> 需要 tab 切换 + 表格时，直接选 G-4 的「带切换tab」变体（内联 G-5 的 MTD Tabs + ghost 按钮二级筛选），无需独立渲染 G-5。

**G-3 复杂档筛选器关键设计**：

1. **配置驱动**：组件接 `groups: FilterGroup[]` 配置渲染，不写死字段。`FilterGroup = { label, fields }`；`FilterField = { key, label, type:'select'|'input'|'daterange'|'switch', options?, placeholder?, width? }`。
2. **关注点分离**：组件只负责「收集筛选条件」，`v-model` 吐出扁平 `{ [key]: value }` 值对象；真过滤在父组件 `computed`，组件不持有业务数据。
3. **多行分组布局**：每行 `.adv-row` 用 `display:flex; align-items:center`；左 label 列固定宽(`width:5em` 右对齐)；右侧字段区 `flex-wrap:wrap`。
4. **收起/展开**：`expanded` 默认 `true`；收起时只显示第 0 行；分组 >1 才出「收起/展开」按钮。
5. **快捷筛选方案（真功能）**：Dropdown 内列已存方案 + 「保存当前条件为方案」。点应用后表格要真变回保存时的结果。
6. **装饰一致**：白底+`--radius-3`圆角、无边框无阴影、`padding:--card-padding`、控件 `size="small"`。

> 完整组件源码见 `dashboard-app/src/modules/AdvancedFilterBar.vue`。交互范式见 `interaction-patterns.md` 范式 D。

**推荐图表**：

- D-1：可不用图表，纯数字指标即可。
- D-3（可选）：`line` 简单趋势 或 D-2（`gauge`/`liquid`）进度。

**生成要点**：

1. 筛选器必须用**复杂档**（AdvancedFilterBar），不能用简单档。
2. 表格是页面主体，占最大空间，必须带操作列（编辑/删除/状态操作等）。
3. 指标卡片和趋势图可选，仅提供「数据上下文」，不是焦点。
4. 表格带完整功能：排序 + 筛选联动 + 分页 + 批量操作 + 行操作。
5. 信息递进：复杂筛选定位 → 概要数字(可选) → 表格操作明细。

**自检**：

- [ ] G-3 使用复杂档筛选器（多行分组+方案+收起），非简单档。
- [ ] 表格（G-4）是页面主体，占 60%+ 空间。
- [ ] 表格带操作列（编辑/审批/删除等），非纯只读。

## 八、黄色主题 + 底部悬浮切换栏（可选装配项）

> 完整主题机制（双层联动、token 取值表、React/Vue3 接入代码）见 `references/theme-system.md`，本节只说明**看板页何时装配、切换栏放在哪、长什么样**。

**触发条件**：仅当用户明确要求"支持主题切换""加个黄色版本""要美团黄主题"等诉求时才装配本节内容；未提及主题切换时，看板页默认只用 `primary` 主题，不生成切换栏。

**装配方式**：

1. 应用最外层（路由出口之外、全局只挂一次）包一层 `ThemeProvider`（React）或调用 `useTheme()` 组合式函数完成初始化（Vue3），参考 `references/theme-examples/theme.react.tsx` / `theme.vue3.ts`。
2. 在页面根节点（或全局布局组件，如 `App.tsx` / `Layout.vue`）追加一个**底部悬浮切换栏**，与看板页其余内容同层级渲染，不占据页面正常文档流：
   - `position: fixed; bottom: 24px; right: 24px; z-index: 9999`（若页面已有底部悬浮元素如"回到顶部"按钮，本切换栏放在其左侧，间距 `--gap-elem`，避免重叠）。
   - 深色悬浮胶囊背景 `rgba(15, 23, 42, .92)` + `backdrop-filter: blur(12px)`，圆角 `--radius-2`，内部两个分段按钮（`工具蓝` / `美团黄`），当前选中项高亮（半透明白色底 `rgba(255,255,255,.16)` + 白色文字），未选中为 `rgba(255,255,255,.6)` 文字。
   - 每个分段按钮前置一个 8px 圆点色块，色值取该主题的 `--color-brand-primary` 取值，作为主题预览色标。
   - 点击分段按钮调用 `setTheme(themeKey)`，同时触发 MTD 组件层 CSS 替换与业务 token 层重新赋值（两层联动细节见 `theme-system.md` §3）。
3. 该切换栏是**全局悬浮控件**，不属于任何一个看板编排模式（数据通览/AI总结/筛选+表格/工作台）的模块清单，不在装配示例的模块列表中出现，只在"用户要求主题切换"时作为页面外层的附加装配项处理。
4. 黄色主题下，看板页内所有走 `var(--color-brand-primary)` / `var(--chart-1)` 等中性 token 的元素（指标卡强调色、图表首位分类色、Tab 选中态等）会自动随主题联动；**不要**为黄色主题额外写一套硬编码色值或按主题名做条件分支。

**自检**：

- [ ] 仅在用户明确要求主题切换时才装配，未要求时不生成切换栏。
- [ ] 切换栏为页面级悬浮控件，`fixed` 定位，不挤占看板内容区布局。
- [ ] 与页面已有的其他悬浮控件（回到顶部等）不重叠，横向依次排列。
- [ ] 主题切换同时驱动 MTD 组件层 CSS 与业务 Token 层，两层不脱节。
- [ ] 业务代码不出现颜色字面量硬编码或按主题名分支，全部走中性 token。

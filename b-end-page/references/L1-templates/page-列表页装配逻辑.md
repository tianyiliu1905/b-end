# L1 · 列表页装配逻辑

本文件描述**列表页**如何从模块库装配成页面。所有模块的通用规则（核心视觉、可配参数）统一维护在 L2 模块规范中，本文件只负责说明「列表页用哪种编排模式、按什么逻辑组合模块」。

---

## 〇、技术栈判断（最先执行）

> ⚠️ **生码前必须先确认技术栈**，不同技术栈的组件 API、CSS 类名前缀、DOM 结构存在显著差异。沿用主 SKILL.md §4.0 的框架探测方式，此处不重复。

---

## 一、装配逻辑：默认外壳 + 两步装配

### 默认外壳：全局导航（G-1 顶部导航 + G-2 侧边栏）

> ⚠️ **任何列表页默认包含顶导和侧导**。除非用户明确要求"不需要导航"或目标代码已有导航组件。

```
G-1 顶部导航（fixed 顶部，52px 高）
  └─ G-2 侧边栏（fixed 左侧，168px / 收起 60px）
      └─ app-content（主内容区，灰底 #F3F3F4）
          └─ 列表内容区（筛选器 → 操作栏 → 表格 → 分页器）
```

**加载规则**：生成列表页时，默认加载 G-1 和 G-2。顶导和侧导的菜单数据根据业务场景合理虚构，当前页面对应的菜单项设为选中态。

**场景 B（增量/在已有页面上增加模块）**：如果目标代码文件中已经存在 sidebar 组件或 header/topnav 组件（如 `Layout.Sider`、`Sidebar`、`Layout.Header`、`DashboardLayout` 等），则不重复添加 G-1/G-2，只输出内容区代码即可。

> 简言之：**默认加，除非用户说不加，或目标已经有。**

### 两步装配（编排模式 + 模块）

```
第一步（主维度）：先定编排模式 → CRUD管理 / 树形层级 / 主从详情 / 看板 / 时间轴 / 指标+明细
          以"数据形态"为判断依据（纯表格？有树形层级？需要左右主从？卡片拖拽？事件流？先总后分？）

第二步（按需叠加）：扫描 prompt，按功能需求匹配 G/D 模块
          用户每多描述一项功能 → 多叠加一个对应模块
          叠加受编排模式约束：时间轴模式不叠加 G-4 表格，看板模式不用 G-3 筛选器
```

> **编排模式是约束，模块是在约束内的填充。** 先决定用哪种模式，再在模式内按用户描述叠加模块——不需要先推断"列表类型"再套底座，直接读 prompt 里说了什么、就叠什么模块。

## 二、第一步：选编排模式（六选一）

这是装配的主维度。不同模式决定了页面骨架结构、交互模式和信息架构。差异点不是表格列配置（那只是 G-4 的 preset），而是页面整体的布局骨架。

| 编排模式 | 数据形态 | 骨架结构 | 典型场景 |
|---------|---------|---------|---------|
| CRUD管理（CRUD） | 纯表格，一个对象=一行 | 筛选 → 操作栏 → 全宽表格 → 分页 | 人员/订单/商品管理 |
| 树形层级（Tree） | 数据有树形层级关系 | 左树导航(240px) + 右(筛选+表格) | 组织架构/目录/分类管理 |
| 主从详情（Master-Detail） | 需要左右主从结构 | 左列表(360px) + 右详情面板 | 邮件/工单/聊天 |
| 看板（Kanban） | 卡片拖拽/状态流转 | 多列泳道（非表格形态） | 任务管理/工单流转/招聘管道 |
| 时间轴（Timeline） | 事件流/操作记录 | 时间轴 + 事件卡片（非表格形态） | 操作日志/变更记录/审计追溯 |
| 指标+明细（Metric+Detail） | 先看汇总再看明细 | 汇总指标卡片 → 趋势图(可选) → 明细表格 | 财务流水/结算明细/数据分析 |

**判断口诀**：

> 看到「管理列表」「人员列表」「商品列表」「XX管理」「标准增删改查」→ **CRUD管理**
> 看到「组织架构」「分类管理」「目录」「层级」「树形」→ **树形层级**
> 看到「左右」「主从」「列表+详情」「工单处理」「邮件列表」→ **主从详情**
> 看到「看板」「拖拽」「状态流转」「泳道」→ **看板**
> 看到「操作记录」「日志」「变更记录」「审计」「时间线」→ **时间轴**
> 看到「流水」「结算明细」「先总后分」「指标+明细」→ **指标+明细**

**决策树**：

```
用户要看的数据是什么形态？
├─ 纯表格（一个对象=一行）
│   ├─ 数据有树形层级关系？        → 树形层级
│   ├─ 需要左右主从结构（即时预览详情）？  → 主从详情
│   └─ 标准增删改查？              → CRUD管理
├─ 卡片拖拽/状态流转（对象在不同状态间移动）？ → 看板
├─ 事件流/操作记录（强调时间线）？          → 时间轴
└─ 先看汇总数据，再看明细？               → 指标+明细
```

> **优先级原则**：用户明确要求某种模式时直接采用；未指定时按数据形态推断。注意旧的 L1~L5 命名（信息卡片列表/数据分析表格/流水日志/财务流水）已废弃，它们本质上都是 CRUD管理的不同 G-4 preset（不同 columns 配置），不构成独立模式。

> **模式间差异在于页面骨架/布局结构，而非表格内的列配置。** 每个模式都可以与 G-1/G-2、G-3/G-4、D-n 模块组合；List-2、List-3、G-5 仅是 G-4 内部逻辑 ID，不作为独立模块选型。

## 三、第二步：按需叠加（触发词 → 模块映射）

编排模式选定后，**直接扫描 prompt**：用户每多描述一项功能需求，就从下表匹配一个模块叠加。

| 用户多说了什么（触发词） | 叠加模块 |
|--------------------------|---------|
| 搜索 / 筛选 / 时间段 / 状态下拉 | G-3 筛选器栏 |
| 新增 / 导出 / 批量操作 / 结果数 | G-4 内联操作栏（List-2） |
| 数据表格 / 明细列表 | G-4 数据表格 |
| 分页 / 翻页 | G-4 内联分页器（List-3） |
| Tab切换 / 状态切换 | G-4 带切换tab变体（G-5） |
| 概览指标 / 核心数字 / 汇总 | D-1 指标卡片组 |
| 趋势 / 走势 / 同比环比 | D-3 折线图/面积图 |
| 树形导航 / 左侧树 / 层级分类 | MTD Tree 组件 |
| 时间线 / 操作记录 / 流程进度 | MTD Timeline 组件 |

> **基础底座**：任何列表页默认至少包含「G-3 筛选器栏 + G-4 数据表格」——这是列表成立的最小集。G-4 内部按需启用操作栏（List-2）、分页器（List-3）和切换tab（G-5）。主从详情和看板模式的基础底座见各自模式详解。

## 四、编排模式 × 模块：约束自检

| 编排模式 | 可叠加的模块 | 约束提示 |
|---------|-------------|---------|
| CRUD管理 | G-3 + G-4(含操作栏/分页) | ⚠️ G-4 至少一列弹性（不设 width）；必须有新增入口；支持批量操作 |
| 树形层级 | 左Tree + 右(G-3 + G-4) | ⚠️ 左侧树宽 240px；右侧表格与 CRUD 一致；用 `mtd-tree`（非手写 ul/li） |
| 主从详情 | 左列表 + 右详情面板 | ⚠️ 不用 G-3/G-4 标准表格；左面板 360px 卡片摘要；右侧详情区块化 |
| 看板 | 多列泳道卡片 | ⚠️ 不用 G-3/G-4；支持拖拽；白底卡片+浅描边（非灰底卡片） |
| 时间轴 | Timeline + EventCard | ⚠️ 不用 G-4 表格；按时间倒序；用 `mtd-timeline`（非 div 手写） |
| 指标+明细 | D-1 + D-3(可选) + G-4(含操作栏/分页) | ⚠️ 指标与明细联动；金额列有正负色标；支持导出 |

> 时间轴模式当数据量大（>50条）且不需要强调时间因果时，可降级为 CRUD管理 + Table 表格形态，此时退化为 CRUD 的一种 preset。

## 五、G-4 表格变体选择

同一个 G-4 模块通过 columns 配置覆盖不同业务场景。CRUD管理和指标+明细模式均使用 G-4，通过以下 preset 区分：

| preset | 首列特征 | 数值列 | 状态列 | 操作列 | 场景 |
|--------|---------|--------|--------|--------|------|
| 基础管理表 | 单行文本 | 普通数值 | Tag | 编辑/删除 | 通用管理 |
| 图文信息表 | 图片+名称+ID | 无 | Tag | 多个竖排链接 | 人员/对象管理 |
| 数据分析表 | 缩略图+名称 | 涨跌百分比 | 无 | 趋势 | 商品数据分析 |
| 流水明细表 | 时间 | 金额正负色标 | 类型 | 详情 | 财务流水 |
| 日志追溯表 | 时间 | 无 | 操作类型 | 操作人 | 操作日志 |
| 排名榜单表 | 排名序号 | 指标数值 | 无 | 无 | TOP排名 |

> **快速决策**：核心列是「对象+状态+操作」→ 基础管理表 | 有「图片+名称」→ 图文信息表 | 是「数值+涨跌」→ 数据分析表 | 是「时间+金额正负」→ 流水明细表 | 是「时间+操作类型」→ 日志追溯表 | 是「排名+指标」→ 排名榜单表。变种可混搭。

## 六、装配示例（按编排模式分组）

以下示例先按**编排模式**归类，体现「模式是主维度」；每个示例再展示「扫描 prompt → 直接叠加模块」。

### （一）CRUD管理列表 —— 标准增删改查

**例1 · 商品管理列表**

Prompt：「做一个商品管理列表，支持搜索商品名称、按分类和状态筛选，表格带图片列，可以新增和编辑」

- 编排模式：**CRUD管理**（标准增删改查）
- 按需叠加：基础底座 → G-3 + G-4；"搜索商品名称" → G-3 Input；"分类和状态筛选" → G-3 Select；"图片列" → G-4 图文信息表变体；"新增和编辑" → G-4 操作栏
- **最终**：CRUD管理[ G-3(简单档) + G-4(图文信息表 + 操作栏 + 分页器) ]

### （二）树形层级列表 —— 层级分类驱动

**例2 · 分类管理**

Prompt：「商品分类管理，左侧树形导航展示类目层级，选中后右侧展示该分类下的商品列表」

- 编排模式：**树形层级**（左树右表）
- 按需叠加：基础底座 → 左Tree + 右(G-3 + G-4)；"类目层级" → MTD Tree；"面包屑" → MTD Breadcrumb
- **最终**：树形层级[ 左: Tree(240px) | 右: Breadcrumb + G-3 + G-4(基础管理表 + 操作栏 + 分页) ]

### （三）主从详情列表 —— 左右分屏

**例3 · 工单处理**

Prompt：「工单管理页面，左侧工单列表，点击后右侧展示工单详情和处理操作」

- 编排模式：**主从详情**（左列表右详情）
- 按需叠加：基础底座 → 左列表 + 右详情面板；"搜索" → 左面板 Input；"详情" → 右面板 Descriptions；"处理操作" → 右面板 Button
- **最终**：主从详情[ 左: 卡片摘要列表(360px) | 右: 详情头部 + 基本信息区 + 操作记录区 + 操作按钮 ]

### （四）看板泳道列表 —— 状态流转

**例4 · 任务管理看板**

Prompt：「任务管理看板，待办、进行中、已完成三列，卡片可以拖拽流转」

- 编排模式：**看板**（多列泳道）
- 按需叠加：基础底座 → 泳道容器 + 卡片；"筛选" → G-3 顶部；"视图切换" → Radio.Group
- **最终**：看板[ G-3 + 视图切换 + 泳道{ 待办 | 进行中 | 已完成 } + 拖拽卡片 ]

### （五）时间轴列表 —— 事件流

**例5 · 操作日志**

Prompt：「操作日志页面，按时间线展示用户操作记录，支持按日期和操作类型筛选」

- 编排模式：**时间轴**（时间轴 + 事件卡片）
- 按需叠加：基础底座 → G-3 + Timeline；"日期筛选" → G-3 DatePicker；"操作类型筛选" → G-3 Select；"加载更多" → 底部 Button
- **最终**：时间轴[ G-3(日期+类型+操作人) + Timeline(倒序) + 加载更多 ]

### （六）指标+明细列表 —— 先总后分

**例6 · 财务流水**

Prompt：「财务流水页，顶部显示总金额和订单数指标，下面是明细表格，支持导出」

- 编排模式：**指标+明细**（先总后分）
- 按需叠加：基础底座 → G-3 + G-4；"总金额和订单数" → D-1；"明细表格" → G-4 流水明细表变体；"导出" → G-4 操作栏
- **最终**：指标+明细[ D-1 + G-3 + G-4(流水明细表 + 导出 + 分页器) ]

## 七、各编排模式详细规格

> 以下为每种模式的完整规格，包含页面骨架、模块组装、关键要点和自检清单。装配时命中某模式后，阅读对应章节获取详细规格。

### 7.1 CRUD管理列表（CRUD）

**何时用**：人员管理（员工/客户/供应商）、订单管理（外卖/到店/退款）、商品/SKU 管理、任何标准的增删改查列表。

**核心特征**：标准全功能单表：筛选 → 操作栏 → 全宽表格 → 分页。最通用的列表页模式。

**页面骨架**：

```
┌─────────────────────────────────────────────────┐
│ G-1 顶部导航                                      │
├─────────────────────────────────────────────────┤
│ G-3 筛选器（搜索 + 筛选项 + 状态Tab）             │
├─────────────────────────────────────────────────┤
│ G-4 数据表格模块（内联操作栏：结果数 | 导出 · 新增）  │
├─────────────────────────────────────────────────┤
│ G-4 表格主体（全宽，列配置驱动差异）                  │
│ ┌───┬──────────┬──────┬──────┬──────┬─────┐    │
│ │ ☐ │ 基本信息  │ 字段1 │ 字段2 │ 状态  │ 操作│    │
│ ├───┼──────────┼──────┼──────┼──────┼─────┤    │
│ │   │ ...      │ ...  │ ...  │ Tag  │ 链接│    │
│ └───┴──────────┴──────┴──────┴──────┴─────┘    │
├─────────────────────────────────────────────────┤
│ G-4 内联分页器（逻辑 ID：List-3）                    │
└─────────────────────────────────────────────────┘
```

**交互要点**：

- 支持批量选择 + 批量操作（使用 G-4 内联操作栏）
- 行点击可跳转详情页（或打开抽屉）
- 支持列排序
- 筛选 + 搜索联动刷新表格

**自检**：

- [ ] 页面结构：G-3 → G-4（内含操作栏、表格、分页器）
- [ ] G-4 至少一列弹性（不设 width）
- [ ] 有新增入口（G-4 内联操作栏主按钮）
- [ ] 有批量操作能力（selection + batch actions）
- [ ] 空态展示（mtd-empty）

### 7.2 树形层级列表（Tree）

> 左侧树面板对应 L2 模块 **G-6 分类导航 (Category Tree Nav)**，可在「模块库」页面独立浏览；右侧表格仍复用 G-4。详见 `references/L2-modules/index.json` 的 `G-6` 条目。

**何时用**：组织架构管理（部门树 → 人员列表）、分类/目录管理（类目树 → 商品列表）、地区管理（省市区树 → 门店列表）、权限管理（菜单树 → 角色/权限配置）、文件管理（文件夹树 → 文件列表）。

**与 CRUD管理 的本质差异**：CRUD 是全宽表格；树形层级是**左树右表分屏**，通过树节点选择来筛选/切换右侧表格数据。左侧是**树形结构**（层级关系），不是同质列表。

**页面骨架**：

```
┌─────────────────────────────────────────────────┐
│ G-1 顶部导航                                      │
├────────────┬────────────────────────────────────┤
│ 左树面板    │ 右内容面板                           │
│ (240px)    │                                    │
│            │ 面包屑: 全部 > 生活服务 > 保洁         │
│ [搜索树]   │ ───────────────────────────────── │
│ ▼ 全部      │ G-3 筛选器                        │
│   ▼ 生活服务│ ───────────────────────────────── │
│     ● 保洁  │ G-4 内联操作栏（新增分类 · 新增项目） │
│     ○ 维修  │ ───────────────────────────────── │
│     ○ 搬运  │ G-4 表格主体                         │
│   ▶ 餐饮    │ ┌──────┬──────┬──────┬─────┐     │
│   ▶ 零售    │ │ 名称  │ 状态  │ 更新时间│操作 │     │
│            │ ├──────┼──────┼──────┼─────┤     │
│ [+ 新增节点]│ │ ...  │ Tag  │ ...  │ 链接│     │
│            │ └──────┴──────┴──────┴─────┘     │
├────────────┴────────────────────────────────────┤
│ 右侧 G-4 内联分页器（逻辑 ID：List-3）             │
└─────────────────────────────────────────────────┘
```

**左面板树形导航**：

```vue
<mtd-tree
  :data="treeData"
  :default-expand-all="false"
  :highlight-current="true"
  @node-click="onNodeClick"
>
  <template #default="{ node }">
    <span class="tree-node">
      <span>{{ node.label }}</span>
      <span class="tree-count">({{ node.count }})</span>
    </span>
  </template>
</mtd-tree>
```

**L3 实现**：

| 位置 | MTD 组件 | 说明 |
|------|---------|------|
| 树容器 | `mtd-tree` | `:data`, `@node-click`, `:highlight-current` |
| 树搜索 | `mtd-input` | 树节点过滤 |
| 面包屑 | `mtd-breadcrumb` | 展示当前路径 |
| 右侧表格 | G-4 DataTable | 标准配置 |
| 新增节点 | `mtd-button` | 树底部 |

**交互要点**：

- 树节点点击 → 右侧表格数据联动刷新
- 树支持展开/收起、搜索过滤
- 树节点右键菜单（新增子节点/重命名/删除）
- 面包屑路径展示当前层级位置
- 树节点可显示子项数量 badge

**视觉**：

- 左面板：白底，固定宽度 200-260px，overflow-y: auto
- 选中节点：浅蓝底 + 蓝色文字
- 右面板：标准 CRUD 布局（筛选+操作栏+表格）
- 左右之间：1px divider 竖线

**⚠️ 左右两栏等高 + 表格分页贴底（踩坑沉淀）**：

树形层级列表的左树面板高度由内容撑开，右侧 G-4 表格若不做处理会呈现"自然内容高度"，导致左右两栏参差不齐、表格分页器悬在内容正下方而不是贴底。做法：

```jsx
<div style={{
  display: 'grid',
  gridTemplateColumns: '240px 1fr',
  gap: 'var(--gap-module)',
  flex: 1,                                    // 跟随父级 PageLayout 的剩余高度
  minHeight: 'calc(100vh - 52px - 48px)',      // 兜底：内容不足一屏时仍撑满可视区
}}>
  <div className="dash-card" style={{ display: 'flex', flexDirection: 'column', overflow: 'auto' }}>
    {/* 左树面板：内容自然高度即可，用 overflow:auto 兜底超长树 */}
  </div>
  <div style={{ display: 'flex', flexDirection: 'column', minWidth: 0 }}>
    {/* 右表格模块：flex:1 + minHeight:0 让表格撑满与左侧同等高度，分页器贴底 */}
    <ModuleWrapper moduleId="G-4 数据表格" style={{ flex: 1, minHeight: 0 }} />
  </div>
</div>
```

`flex:1` 要在组件内部逐层传递才会生效：`ModuleWrapper`（外层）→ `.dash-card`（卡片本体）→ `Table-wrapper`（表格容器）都要设置 `flex:1; min-height:0`，表格本体撑满后分页器才会被推到卡片底部，而不是紧跟在表格最后一行下面。

**必须同时保留 `minHeight` 兜底，不能只写 `flex:1`**：`flex:1` 依赖祖先链上存在一个「有确定高度」的 flex 容器才能生效；如果 `PageLayout` 的 `.content` 只是 `flex:1` 而它自己的父级没有确定高度（常见于纯内容区、无固定视口高度的壳层），`flex:1` 会退化成没有可分配空间，整个网格塌缩成内容自身高度，下方留出一大块空白。之前尝试把 `minHeight: calc(100vh - 52px - 48px)` 完全去掉、只留 `flex:1`，页面就复现了这个问题；加回 `minHeight` 作为兜底后恢复正常。因此两者要同时保留：`flex:1` 负责"有空间就撑满"，`minHeight` 负责"没有确定空间时也不塌缩"。

**自检**：

- [ ] 左树右表分屏布局
- [ ] 树节点点击联动右侧数据
- [ ] 用 `mtd-tree`（非手写 ul/li）
- [ ] 有面包屑路径提示
- [ ] 树支持搜索/过滤
- [ ] 支持新增/编辑/删除树节点
- [ ] 左右两栏等高，右侧表格 `flex:1 + minHeight:0` 逐层传递到 Table-wrapper，分页器贴底；容器同时保留 `minHeight` 兜底，不单独依赖 `flex:1`

| 核心目的 | 查看明细记录（表格为主） | 监控/观测数据（图表为主） |
| 指标卡片 | 1行，为明细提供上下文 | 多行多组，是核心内容 |
| 表格角色 | 主角（占页面60-70%） | 配角（辅助明细补充） |
| 图表 | 可选，简单趋势线 | 必须，多种图表类型 |
| 用户行为 | 浏览明细 → 定位具体记录 | 观察趋势 → 发现异常 |

**L3 实现**：

| 位置 | 模块 | 说明 |
|------|------|------|
| 状态Tab | `mtd-tabs` / `mtd-radio-group` | 切换数据范围 |
| 指标卡片 | D-1 MetricCards | 复用看板指标卡片模块 |
| 趋势图 | D-3 TrendChart (可选) | 简单折线图 |
| 汇总卡片 | H SummaryCard (可选) | 财务场景黄底卡片 |
| 操作栏 | G-4 内联操作栏（逻辑 ID：List-2） | 结果数+导出 |
| 明细表格 | G-4 DataTable | 标准配置 |

**交互要点**：

- Tab/时间范围切换 → 指标和明细联动刷新
- 指标卡片可点击 → 筛选明细（如点击"退款"指标卡片 → 表格只展示退款记录）
- 明细表格支持导出
- 金额正负色标（正绿负红）

**视觉**：

- 指标卡片区：白底卡片，横向排列，间距 `--gap-module`
- 趋势图区：白底卡片，高度 180-240px
- 明细表格区：标准 Table 视觉
- 各区块间间距 `--gap-module`

**自检**：

- [ ] 有顶部聚合指标（指标卡片或汇总卡片）
- [ ] 表格为主体内容（占页面大部分空间）
- [ ] 指标与明细联动（切换范围同步刷新）
- [ ] 金额列有正负色标
- [ ] 支持导出

## 八、黄色主题 + 底部悬浮切换栏（可选装配项）

> 完整主题机制（双层联动、token 取值表、React/Vue3 接入代码）见 `references/theme-system.md`，本节只说明**列表页何时装配、切换栏放在哪、长什么样**。

**触发条件**：仅当用户明确要求"支持主题切换""加个黄色版本""要美团黄主题"等诉求时才装配本节内容；未提及主题切换时，列表页默认只用 `primary` 主题，不生成切换栏。

**装配方式**：

1. 应用最外层（路由出口之外、全局只挂一次）包一层 `ThemeProvider`（React）或调用 `useTheme()` 组合式函数完成初始化（Vue3），参考 `references/theme-examples/theme.react.tsx` / `theme.vue3.ts`。
2. 在页面根节点（或全局布局组件）追加一个**底部悬浮切换栏**，与列表页其余内容同层级渲染，不占据页面正常文档流：
   - `position: fixed; bottom: 24px; right: 24px; z-index: 9999`（若页面已有其他底部悬浮元素，本切换栏放在其左侧，间距 `--gap-elem`，避免重叠）。
   - 深色悬浮胶囊背景 `rgba(15, 23, 42, .92)` + `backdrop-filter: blur(12px)`，圆角 `--radius-2`，内部两个分段按钮（`工具蓝` / `美团黄`），当前选中项高亮（半透明白色底 `rgba(255,255,255,.16)` + 白色文字），未选中为 `rgba(255,255,255,.6)` 文字。
   - 每个分段按钮前置一个 8px 圆点色块，色值取该主题的 `--color-brand-primary` 取值，作为主题预览色标。
   - 点击分段按钮调用 `setTheme(themeKey)`，同时触发 MTD 组件层 CSS 替换与业务 token 层重新赋值（两层联动细节见 `theme-system.md` §3）。
3. 该切换栏是**全局悬浮控件**，不属于任何一个列表编排模式的模块清单，不在装配示例的模块列表中出现，只在"用户要求主题切换"时作为页面外层的附加装配项处理。
4. 黄色主题下，列表页内所有走 `var(--color-brand-primary)` 等中性 token 的元素（主操作按钮、Tab 选中态、链接色等）会自动随主题联动；**不要**为黄色主题额外写一套硬编码色值或按主题名做条件分支。

**自检**：

- [ ] 仅在用户明确要求主题切换时才装配，未要求时不生成切换栏。
- [ ] 切换栏为页面级悬浮控件，`fixed` 定位，不挤占列表内容区布局。
- [ ] 与页面已有的其他悬浮控件不重叠，横向依次排列。
- [ ] 主题切换同时驱动 MTD 组件层 CSS 与业务 Token 层，两层不脱节。
- [ ] 业务代码不出现颜色字面量硬编码或按主题名分支，全部走中性 token。

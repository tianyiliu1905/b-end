# L1 · 详情页装配逻辑

本文件描述**详情页**如何从公共模块库装配成页面。详情页与表单页共用同一套四层架构（Page → Module → Primitive → Component）与同一批公共模块，**差异只在于详情页重"展示"、表单页重"录入"**。

> ⚠️ **模块复用原则**：详情页优先复用 FD 系列及适用的 Form 系列模块；当前可用的详情专属模块只有 Detail1 Tab、Detail2 描述列表和 Detail3 附件预览。状态流程与数据统计卡片规范未完成，不路由到独立模块；相关需求需向用户说明当前规范不覆盖，避免临时猜测实现。时间线直接调用 MTD `Timeline`，关联信息区使用 Form2 + 文字链接。

## 一、装配逻辑：默认外壳 + 两步装配

### 默认外壳：全局导航（G-topnav + G-sidebar）

> ⚠️ **任何落地页必须默认包含顶导和侧导**。抽屉浮在已有页面之上，不包含顶导侧导。

```
G-topnav（顶导，fixed 顶部，52px 高）
  └─ G-sidebar（全局侧导，fixed 左侧，168px / 收起 60px）
      └─ app-content（主内容区，灰底 var(--bg-page)）
          └─ 承载容器（page-container → page-card 白卡）
```

**加载规则**：生成落地页时，默认加载 `General-Layout.tsx`（顶导+侧导一体化模板），将详情内容作为 children 嵌入 `app-content` 内。顶导和侧导的菜单数据根据业务场景合理虚构，当前页面对应的菜单项设为选中态。

### 两步装配（容器 + 模块）

```
第一步（容器语义，二选一）：匹配承载容器 → 落地页 / 抽屉
          默认落地页；用户明确提到「抽屉」才切换
          （复用 FD1 的落地页/抽屉外壳，不使用其主从落地页和表单弹窗分支）

第二步（按需叠加）：扫描 prompt，按页面结构从上到下铺展示类模块
          表头信息区 → Tab 切换（可选）→ 内容区（各种展示样式）→ 操作区
```

> **容器语义匹配二选一，默认落地页。** 详情页不像表单页那样需要“顺序/主从”细分；信息按维度切换时使用 Detail1。弹窗容器仅开放给表单页，详情页不作为可选容器。

---

## 二、第一步：选承载容器（落地页 / 抽屉）——复用 FD1

详情页直接复用 `FD1-presentation-container.md` 中的落地页和抽屉外壳，不使用主从落地页和表单弹窗分支。

选哪种容器，**以「信息量 / 复杂度」为主，以「与主流程的关系」为辅**：

| 承载方式 | 适用信息量 / 复杂度 | 与主流程的关系 | 典型场景 |
| --- | --- | --- | --- |
| 抽屉（Drawer） | 中等或较少信息，可含少量分组 | 需要边看背后列表边查看详情，不想跳走 | 快速预览、入园信息查看、列表行展开详情 |
| 落地页（Page） | 信息多 / 多分组 / 含 Tab / 含时间线等重型结构 | 本身就是独立任务，需要完整空间 | 商品管理详情、违规详情、门店详情、投放计划详情 |

**判断口诀**：

> **默认落地页。** 用户明确要求抽屉时才切换；若要求弹窗，说明当前弹窗容器规范未完成，并建议改用抽屉或落地页。
> 命中重型模块（Tab、多分组、时间线）但用户没指定容器时，直接使用落地页。

---

## 三、第二步：按需叠加（触发词 → 模块映射）

容器选定后，**直接扫描 prompt**：用户每多描述一项需求，就从下表匹配一个模块叠加进容器。不需要先判断意图类型，触发词命中即叠加。

**下表「叠加模块」列已标注复用来源**——标 `FD*`/`Form*` 的直接读对应模块文件；标 `Detail*` 的是详情页新增模块。

| 用户多说了什么（触发词） | 叠加模块 | 所属页面结构区 |
| --- | --- | --- |
| 分组 / 多个区域 / 分几块展示 | 分组分段（**Form2** GroupSection，复用） | 内容区 |
| Tab / 多维度 / 切换查看 / 不同面板 | Tab 切换（**Detail1** TabPanel，新增） | Tab 区 |
| 表格 / 列表 / 数据明细 / 记录 | 只读数据表格（**FD3** ReadonlyTable，复用） | 内容区 |
| 时间线 / 日志 / 操作记录 / 流程进度 | MTD `Timeline` 组件（直接调用，无 L2 模块） | 内容区 |
| 状态 / 进度 / 审批流 / 流程节点 | 当前规范不覆盖，说明限制，不自动生成对应模块 | 内容区 |
| 描述列表 / 键值对 / 基本信息 | 描述列表（**Detail2** DescriptionList，新增） | 内容区 |
| 图片 / 附件 / 文件预览 | 附件预览（**Detail3** AttachmentPreview，新增） | 内容区 |
| 统计 / 指标 / 数据卡片 / 概览 | 当前规范不覆盖，说明限制，不自动生成对应模块 | 内容区 |
| 关联 / 相关信息 / 关联单据 | Form2 分组分段 + 文字链接（直接复用，无独立 Detail 模块） | 内容区 |
| 操作 / 编辑 / 审批按钮 | 操作栏（**Form1** ActionBar，复用） | 操作区 |
| 标题 / 状态标签 / 面包屑 / 返回 | 表头信息区（**FD2** PageHeader + 状态标签原子，复用） | 表头区 |

> **基础底座**：任何详情页默认至少包含「表头信息区」（FD2）——这是详情页成立的最小集（标题 + 返回/面包屑）。其余模块全部按触发词叠加，内容区模块可自由组合。
>
> **操作栏（Form1）默认不叠加**：与表单页不同，详情页本质是信息展示，默认不包含底部操作栏。只有当用户 prompt 中出现操作性描述（如「编辑」「审批」「下架」「删除」「保存」等动作触发词）命中上表 Form1 行时，才叠加 Form1。用户未提及任何操作动作时，不要为了"完整"而自行补加操作栏。
>
> **Tab 与容器不冲突**：「Tab 切换」（Detail1）管详情页**内部**多维度信息如何切换，承载容器（FD1）管整个详情页**对外**用多大的外壳出现，两者可叠加（例如：落地页内部用 Tab 切换查看不同维度数据）。

## 四、装配示例（按承载容器分组）

以下示例先按**承载容器**归类，体现「容器是主维度」；每个示例再展示「扫描 prompt → 直接叠加模块」，并标注每个模块的复用来源。

### （一）落地页 Page —— 信息量大 / 多分组 / 含 Tab

**例1 · 商品管理详情（分组展示 + 操作按钮）**

Prompt：「服务商品管理详情页，展示基础信息、服务内容、价格信息，底部有编辑和下架按钮」

- 承载容器：**落地页**（复用 FD1，多分组，信息量大）
- 基础底座：表头信息区（FD2）+ 内容区 + 操作区（Form1）
- 按需叠加："分组展示" → 分组分段（Form2）+ 描述列表（Detail2）；"编辑和下架" → 操作栏（Form1）
- **最终**：落地页[ FD2 表头信息区 + Form2 分组分段 + Detail2 描述列表 + Form1 操作栏 ]

**例2 · 操作记录详情（描述列表 + 时间线）**

Prompt：「操作记录详情页，展示基本信息和处理时间线」

- 承载容器：**落地页**
- 基础底座：表头信息区（FD2）+ 内容区
- 按需叠加：基本信息 → Detail2 描述列表；处理时间线 → MTD Timeline
- **最终**：落地页[ FD2 + Detail2 + Timeline ]

**例3 · 投放计划详情（Tab + 数据表格）**

Prompt：「投放计划详情，下方 Tab 切换查看投放记录和效果数据」

- 承载容器：**落地页**
- 基础底座：表头信息区（FD2）+ 内容区
- 按需叠加：Tab 切换 → Detail1；投放记录 → FD3
- **最终**：落地页[ FD2 + Detail1[ FD3 ] ]

### （二）抽屉 Drawer —— 中等或较少信息 / 边看列表边查详情

**例5 · 入园信息-查看状态（侧边展开）**

Prompt：「在列表中点击查看入园信息状态，侧边展开显示入园人信息和审核状态」

- 承载容器：**抽屉**（复用 FD1 抽屉外壳，从列表点击展开，不跳转）
- 基础底座：内容区
- 按需叠加："入园人信息" → 描述列表（Detail2）；审核状态使用 FD2 状态标签原子
- **最终**：抽屉[ FD2 状态标签 + Detail2 描述列表 ]

> 信息变多、出现多分组或 Tab 时，应从抽屉升级为落地页。

## 五、黄色主题 + 底部悬浮切换栏（可选装配项）

> 完整主题机制（双层联动、token 取值表、React/Vue3 接入代码）见 `references/theme-system.md`，本节只说明**详情页何时装配、切换栏放在哪、长什么样**。

**触发条件**：仅当用户明确要求"支持主题切换""加个黄色版本""要美团黄主题"等诉求时才装配本节内容；未提及主题切换时，详情页默认只用 `primary` 主题，不生成切换栏。

**装配方式**：

1. 应用最外层（路由出口之外、全局只挂一次）包一层 `ThemeProvider`（React）或调用 `useTheme()` 组合式函数完成初始化（Vue3），参考 `references/theme-examples/theme.react.tsx` / `theme.vue3.ts`。
2. 在页面根节点（或全局布局组件）追加一个**底部悬浮切换栏**，与详情页其余内容同层级渲染，不占据页面正常文档流：
- `position: fixed; bottom: 24px; right: 24px; z-index: 9999`（落地页承载容器通常空间充裕，可直接放右下角；若页面存在其他底部固定元素，如返回顶部按钮，需错开间距 `--gap-elem`，避免重叠）。
- 深色悬浮胶囊背景 `rgba(15, 23, 42, .92)` + `backdrop-filter: blur(12px)`，圆角 `--radius-2`，内部两个分段按钮（`工具蓝` / `美团黄`），当前选中项高亮（半透明白色底 `rgba(255,255,255,.16)` + 白色文字），未选中为 `rgba(255,255,255,.6)` 文字。
- 每个分段按钮前置一个 8px 圆点色块，色值取该主题的 `--color-brand-primary` 取值，作为主题预览色标。
- 点击分段按钮调用 `setTheme(themeKey)`，同时触发 MTD 组件层 CSS 替换与业务 token 层重新赋值（两层联动细节见 `theme-system.md` §3）。
3. 该切换栏是**全局悬浮控件**，不属于落地页/抽屉承载容器的模块清单，不在装配示例的模块列表中出现，只在"用户要求主题切换"时作为页面外层的附加装配项处理；**抽屉承载容器场景下，切换栏应挂在触发抽屉的宿主页面（如列表页）上，而非抽屉浮层内部**，因为抽屉展开/收起会导致挂载在其内部的悬浮控件随之消失，无法保持全局可见与可用。
4. 黄色主题下，详情页内所有走 `var(--color-brand-primary)` 等中性 token 的元素（FD2 状态标签高亮态、Tab 当前项、关键指标强调色等）会自动随主题联动；**不要**为黄色主题额外写一套硬编码色值或按主题名做条件分支。

**自检**：

- [ ] 仅在用户明确要求主题切换时才装配，未要求时不生成切换栏。
- [ ] 切换栏为页面级悬浮控件，`fixed` 定位，不与页面内其他固定元素重叠。
- [ ] 抽屉承载容器时，切换栏挂在宿主页面而非抽屉内部。
- [ ] 主题切换同时驱动 MTD 组件层 CSS 与业务 Token 层，两层不脱节。
- [ ] 业务代码不出现颜色字面量硬编码或按主题名分支，全部走中性 token。

## 六、装配产物 → 交给 L2 / L3

装配完成后得到「容器 + 模块清单」，接下来：

1. 复用的 FD/Form 模块 → 直接读 `references/L2-modules/{编号}-{模块名}.md`（与表单页共用同一份文件，无需区分）。
2. 新增的 Detail 模块 → 同样读 `references/L2-modules/{编号}-{模块名}.md`。
3. 模块内具体用什么 MTD 组件、组件 API → 查 **L3**（调用 `mtd-rag.js` 实时查询知识库）。
4. 页面视觉规则 → 读取 FD1 承载容器及命中的 L2 模块，不再读取页面级全局样式文件。
5. 主题与切换栏规则 → 查 `references/theme-system.md`（双层联动机制）。

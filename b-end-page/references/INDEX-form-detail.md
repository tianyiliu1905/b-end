# 文生 B 端表单页 / 详情页设计规范索引 — 三层按需加载

**用法**：先查本索引，根据用户需求决定加载哪些规范文件，再读取 `references/` 下对应文件。每层内部按需加载对应文件，绝不一次性全读。

**三层规范各管一件事**：

- **L1 · 页面规范**（page）→ 管「整页怎么装配」：容器语义匹配（默认落地页）+ 按需叠加模块。表单页与详情页各有一份独立装配逻辑；视觉规则由承载容器和命中的 L2 模块提供
- **L2 · 模块规范**（module）→ 管「每个模块内部怎么排」：核心视觉 + 可配参数 + 约束。**FD 系列模块为表单页/详情页共用（FD1 承载容器、FD2 表头信息区、FD3 只读数据表格，及 General-Layout.tsx 顶导+侧导）；Form 系列模块为表单页模块（Form1-Form5、Form6-Form9，其中 Form1/Form2 也适用于详情页，按各自适用范围复用）；Detail 系列模块为详情页专属**
- **L3 · MTD 组件**（component）→ 管「用哪个组件、怎么调」：直接调用本地 MTD 代码组件库，组件知识库（API/示例/注意事项）通过随附脚本 `mtd-rag.js` 实时查询（**不含视觉参数**，外观由代码组件内部保证）；表单页与详情页完全共用同一套 L3

---

## 一、页面规范 · L1（管「整页怎么装配」）

**装配逻辑：容器语义匹配 + 按需叠加（两步），表单页与详情页共用同一套逻辑框架**

1. **第一步（L1 容器语义）**：表单页匹配顺序落地页 / 步骤落地页 / 主从落地页 / 抽屉 / 弹窗；详情页匹配落地页 / 抽屉。表单默认顺序落地页；命中强线性流程切步骤落地页；命中左选右配切主从落地页；明确提到抽屉时切抽屉；明确提到弹窗，或仅有约 1–5 个字段且无分组、无分步的聚焦操作时，可切弹窗
2. **第二步（L2 按需叠加）**：扫描 prompt，按页面结构从上到下铺模块（表头区 → 内容区 → 操作区）；若第一步已选步骤落地页，则其步骤条由 Form4 规范补充（容器侧骨架与联动见 FD1 §3附）。

> 不区分录入型/配置型（差别不大），统一用触发词匹配。L2 模块编号：FD1 承载容器 → FD2 表头信息区 → Form1 操作栏 → Form2 分组分段 → Form3 基础布局 → ... → Form8 公式编辑器；当前可用的详情页专属补充模块为 Detail1/Detail2/Detail3。

## 二、模块规范 · L2（管「每个模块内部怎么排」）

L1 装配出「容器 + 模块清单」后，**只加载清单涉及的模块规范**。每个模块文件含：核心视觉、可配参数、约束。模块的通用规则也统一对应《B端通用模块库》。

> **单文件加载策略**：每个 L2 模块统一读取一份基础 `.md`。单文件同时包含通用设计规则与 MTD 映射/查询/React/Vue3/CSS/踩坑内容；确认技术栈后按需读取对应章节。详见主 SKILL.md §2 单文件架构与分层读取策略。
>
> **FD 系列 / Form 系列 / Detail 系列**：FD 系列（FD1/FD2/FD3 及 General-Layout.tsx 顶导+侧导）是表单页/详情页**共用**模块；Form 系列（Form1-Form5、Form6-Form9）是表单页模块（其中 Form1/Form2 也适用于详情页，按各自适用范围复用）；当前可用的详情页专属 Detail 系列只有 Detail1/Detail2/Detail3。下表「适用页面」列标注 `表单+详情`、`表单专属` 或 `详情专属`。

## 三、MTD 组件 · L3（管「用哪个组件、怎么调」）

模块排版确定后，根据功能匹配 MTD 组件，**通过随附脚本实时查询组件知识库**（API/示例/注意事项），再据此生码。

> ⚠️ **本层不手写视觉参数或 API**。MTD 是本地代码组件库，组件外观（色值/字号/圆角/各种状态）由组件内部封装保证；组件 API 以脚本实时查到的知识库为准，避免臆造或过时。

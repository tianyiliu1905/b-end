# 统一模块描述规范

所有 L2 模块采用下列字段语义。本文统一阅读与维护格式，不改变各页面的专用路由、组件 API 或生成时是否展示 Design Spec。原文中的 ASCII、JSON、参数表和代码仍是有效载体，不要求将所有内容转成 JSON。现有章节编号及内部引用保留；后续新增模块按下表顺序编写。

| 字段 | 必须说明什么 | 现有章节来源 |
| --- | --- | --- |
| 用途与边界 | 用户任务、适用页面、不适用场景、规范模块 ID | 定位、何时用 |
| 输入 | 数据字段、类型、必需项、可配属性、变体；区分模块语义参数和 MTD API | 数据结构、可配参数、变体 |
| 布局与组合 | 内部区域、允许嵌套、父容器约束、已内置能力；复用现有 tokens | 布局、视觉规格、CSS、混排关系 |
| 状态 | 初值、受控归属、派生数据、加载／空／失败状态；静态模块标不适用 | 状态、交互、代码骨架 |
| 事件 | 触发条件、参数、状态变化、联动目标、异步结果；无交互则不适用 | 交互、代码骨架；跨模块关系见 page-contract.md |
| 约束与验证 | 数据与组合前提、禁止组合、用户操作后的可观察结果 | 约束、自检、踩坑 |
| 实现映射 | L3 组件、查询入口、当前框架对应实现 | MTD 实现、组件映射、代码骨架 |

仅描述当前任务需要的字段。现有文档未声明的状态或事件，应根据需求与项目代码补充并标明假设；不能从一段演示代码推断出可用的后端功能。模块语义事件须映射到查询得到的 MTD API，不能直接冒充原生 props。

## 表格选型边界

| 模块 | 用途 | 输入 | 状态与事件 | 组合边界 |
| --- | --- | --- | --- | --- |
| G-4 | 列表／看板中的管理明细 | columns、行数据、rowKey、按需启用的工具栏和分页配置 | 按需绑定筛选、页码、排序、选择；分页／排序／选择／行操作传递有效参数并更新关联结果 | 内置操作栏、分页、可选 tab；不另加 G-5、List-2、List-3 |
| Form5 | 表单中的多行明细录入 | 列字段、编辑控件、行数据、稳定行标识 | 独立行状态；改单元格、增行、删行；提交时与主表单合并并校验 | 全行编辑；按模块混排规则放置，不嵌入 Form.Item；不默认添加管理工具栏 |
| FD3 | 表单／详情中的只读关联列表 | columns、行数据、rowKey、按需分页配置 | 分页更新可见行；有查看入口时传行标识；无编辑状态 | 无增删行及行内编辑；不因“表格”关键词改选 G-4 |
| Form3 | 表单字段的基础布局 | 字段定义、值、布局配置及校验要求 | 字段值、校验反馈；change 更新值，字段联动按需求声明；提交由 Form1／父表单承接 | 配合 Form2 分组、Form1 操作栏及 FD1 容器；复合控件按各自混排规则 |

上述为语义契约，不规定虚构的统一 React/Vue props。底层组件仍按各模块查询 L3。

## 编号与维护

- 列表／看板用 G-1、G-2、G-3、G-4、D-* 等现有索引编号；AntV G2 是图表库名。
- 表单／详情用 FD1–FD3、Form1–Form9、Detail1–Detail3，以 INDEX-form-detail.md 为准。不要用无连字符 G1/G2/G3、F*、D* 缩写指代这些模块。
- 更新时同步命中的索引、装配引用和模块说明；不要全局替换 AntV G2、代码符号或颜色中的字母数字。
- 具体布局和参数在模块文档维护；跨模块数据流按 [页面描述契约](page-contract.md) 维护，不复制两份规则。

## 核对情境

管理订单列表选 G-4；合同表单里增删费用行选 Form5；合同详情里查看关联记录选 FD3；普通表单字段区选 Form3。同一页面可因任务不同同时包含 Form5 和 FD3，不能因为都使用 Table 而合并。
